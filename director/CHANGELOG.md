## [1.0.0] — 2026-09-02

Первая версия. Мастер-скилл: собирает под интервью персонального AI-директора.

### Ядро
- `core/00–06` — доктрина (13 принципов), делегирование, память (два полушария), правила, самоулучшение, протокол, FreeMind-модуль. Модель- и среда-агностик.

### Среды (`adapters/`, 8 + роутер)
- Claude Code, Hermes, OpenClaw, Cursor/Cline/Windsurf, Codex CLI, Qwen Code, n8n AI Agent, generic. Рантайм тонкий — ссылается на `core/`, не дублирует.

### Модели (`models/`, 5 + роутер)
- `anthropic`, `openai-compatible` (таблица на 10 провайдеров), `ru-providers` (GigaChat/YandexGPT), `codex`, `ollama`.

### Память
- Файловая — дефолт; два полушария (LightRAG + PostgreSQL) — апгрейд. Вложенный скилл `memory-setup/lightrag/`.

### Безопасность
- Шаг 0.6 «Снимок перед установкой» + `restore.sh` — автооткат при провале.
- Шаг 0.7 «Инвентаризация» — существующее интегрировать, не затирать.
- `pg_dump` — механический шаг перед write-доступом к БД.
- Память = данные, не команды (защита от инъекции).

### Протокол финала
- Порядок нерушим: разбор диалога → **паттерны и выводы** (не пересказ действий) в LightRAG с ОК → **только потом** commit + push. Push без записи в память = нарушение. В `core/00` (принцип 9), `core/05`, адаптерах.
- Принцип 11 «Сначала — зачем, потом делаю»: перед блоком работы 1 фраза о пользе пользователю, без пошагового комментария.
- Длинные задачи: пороги контекста 70/85%, handoff, ссылка на `context-lifecycle`.

### Активация
- Фаза 1: промокод локально (`FreeMind`/`NR_Stas`→full, `Promo`→lite).
- Фаза 2 (n8n вебхук): спроектирована в `activation.md` + `n8n/README.md`, отложена.

### Качество
- `evals/`: активация, чек-лист сборки, золотые прогоны.
- `skill-conductor` структурная валидация: 10/10.

## [1.2.0] — 2026-09-07

Повторный внешний аудит (Ирина + её AI-директор в Hermes, коммит `01c1c56`). Разбор было/стало по 12 пунктам — `SECURITY_AUDIT_2026-09.md`, раздел v1.2.0. Исправлено:

### Критично
- 🔴 **`install.sh` был сломан:** вызов необъявленной функции `hint` при `set -euo pipefail` → установщик падал сразу после скачивания архива, до копирования. Добавлено определение `hint()`. + изолированный smoke-test прошёл end-to-end.
- **`git push` больше не обязательный финал.** Принцип 10 (было 9) переписан: коммит — только если работа в репо и пользователь просил/согласовал; перед каждым push — показать remote/ветку/файлы + прогон на секреты + **отдельное явное «да, отправляй»**. Force-push запрещён по умолчанию. Правка во ВСЕХ файлах: `core/00`, `core/05`, `SKILL.md`, `adapters/hermes.md`, `adapters/generic.md`, `adapters/{qwen,codex,cursor}`.
- **Пароль PostgreSQL проверяется по-настоящему:** было — `psql` через локальный Unix-сокет (pg_hba `trust` → ложный успех). Стало — TCP через `127.0.0.1` + проверка, что **заведомо неверный** пароль отклоняется; не подтвердилось → `docker compose down` + `exit 1`, а не «продолжаем».

### Архитектура памяти — `MEMORY_BACKEND` (лестница вместо стены)
- Введён параметр `{{MEMORY_BACKEND}}`: `native` / `files` / `lightrag` / `lightrag_postgres`.
- **Дефолт — `native` там, где у среды есть штатная память (Hermes, Cursor), иначе `files`.** Директор запускается на любом уровне.
- Убрано «нет LightRAG → не работать» из `core/00`, `core/02`, `SKILL.md` и адаптеров `generic/qwen/codex/cursor/hermes` (было ~10 мест с копипастой одного правила).
- `lightrag*` — только когда пользователь сам сформулировал потребность; отдельный шаг + экран согласия про приватность (где физически, что уходит).
- Hermes-адаптер: native-память сделана первым и стандартным вариантом; MCP/LightRAG — только если явно попросили.
- `02-memory-lite.md` больше не «урезанная» — полноценный вариант.

### Чувствительные данные — на верхнем уровне
- Новый **принцип 7** в `core/00-director.md`: мед./клиентские данные, пароли, ключи, документы, платёжные данные, чужая переписка **не сохраняются ни в какую память** (native/files/lightrag) без явного разрешения на конкретную запись. Перекрывает автосохранение и `04-improvement.md`.
- Дублировано в `SKILL.md` (принципы), сослано из `core/02`, `core/05`, адаптеров.

### Секреты и терминал (`memory-setup/lightrag/server/install.sh`)
- API-ключ провайдера — теперь `read -r -s` (скрытый ввод), значение в терминал не попадает.
- Команды подключения MCP больше не содержат `LIGHTRAG_API_KEY` открытым текстом — ключ подтягивается из `credentials.txt` (chmod 600) переменной `$LR_KEY` в момент запуска.
- При провале проверки пароля БД полный пароль в подсказке не печатается.

### Инъекция через конфиг
- `DOMAIN` — строгий regex DNS-имени, повторный вопрос при непрохождении.
- `_safe_set` теперь отвергает управляющие символы и переводы строк (ломали структуру `.env`/YAML/Caddyfile).
- API endpoint — проверка `http(s)://`.
- Caddyfile: показ блока + согласие `[y/N]` → `caddy validate` во временном файле → только при успехе `cp` + `reload`.

### Установщик — атомарность и источник
- Проверка `$SRC`/`$SUBDIR` и обязательных файлов **до** касания активной установки.
- Staging → проверка → атомарный swap (`director.new` → `mv`), при сбое активная версия не тронута.
- `DIRECTOR_LOCAL_DIR` — установка из уже проверенной локальной копии без повторного скачивания.
- Без `DIRECTOR_EXPECTED_SHA256` — режим UNVERIFIED с явным `[y/N]`.
- Показ найденных сред + **выбор** целевых (`Куда ставить? номера`), не перезапись всех молча.

### npm-версии
- Все команды/примеры: `@g99/lightrag-mcp-server@1.1.0`, `@modelcontextprotocol/server-postgres@0.6.2` — в `hermes.md`, `codex-cli.md`, `memory-setup/README.md`, `docs/04`, `docs/05`, `server/install.sh`.

### Полный сброс (`docs/06-maintenance.md`)
- `set -euo pipefail`, `mkdir -p ~/backups`, дамп во временный файл → проверка exit code + размера + сигнатуры `PostgreSQL database dump` → `mv` в финальное имя → и **только потом** `docker volume rm`. Без успешного бэкапа до удаления не доходит.

### Diff перед изменением постоянных файлов (Шаг 3 мастера)
- Сборка в staging-каталоге, не поверх активных файлов.
- Показ diff по классам (`SOUL.md` / профиль / MCP / память / doctrine-каталог) + согласие **по каждому классу**.
- Если в `~/.hermes/skills/director-doctrine/` уже персональная версия — отдельный diff, не «обычная перезапись».
- После установки — подтверждение, что реально изменилось.

### Не закрыто (следующий релиз)
- Versioned GitHub Release с официально опубликованным SHA-256 (нужен CI/workflow в репо).
- `image@sha256:` digest-пин контейнеров вместо тегов.
- CI smoke-test установщика + тест «секретов нет в stdout/stderr».

## [1.1.0] — 2026-09-05

Внешний security-аудит (независимый ревьюер, установка на Hermes) — все 12 пунктов подтверждены кодом, зафиксировано в `06_skills/_publish/SECURITY_AUDIT_2026-09.md`. Исправлено:

### Критично (было эксплуатируемо)
- `memory-setup/lightrag/server/install.sh`: убран `eval` на пользовательском вводе (3 места) → `printf -v` с валидацией имени переменной.
- `.env`, `docker-compose.yml`: `umask 077` + `chmod 600` сразу после создания.
- `POSTGRES_PASSWORD` — было захардкожено `rag` во всех шаблонах → генерируется (`openssl rand -hex 20`), плюс рантайм-проверка после старта (образ `gzdaniel/postgres-for-rag` может игнорировать переменную — теперь это не остаётся незамеченным).
- Секреты (пароль, API-ключ) больше не печатаются в терминал целиком — только последние 4 символа + путь к `credentials.txt` (chmod 600).
- Docker больше не ставится автоматически (`curl|sh` + `sudo usermod -aG docker`) — установщик останавливается и показывает инструкцию, запуск — осознанное решение пользователя.
- `lightrag:latest` → закреплён на `1.4.9`.

### Средне
- `adapters/hermes.md`: убран слепой авто-`y` на MCP-разрешения. Показывается список серверов/инструментов, PostgreSQL по умолчанию read-only, write — отдельное явное согласие.
- `memory-setup/lightrag/agents/{AGENTS,CLAUDE}.md`: явное согласие перед подключением удалённой памяти, категории «можно/нельзя сохранять» (жёсткий запрет на мед./клиентские данные без отдельного разрешения), просмотр/экспорт/удаление памяти описаны, файловая память признана нормальным вариантом (не «урезанным»).
- `docs/02-server-setup.md`: `rm -f ~/lightrag/.env` → бэкап + явное согласие вместо тихого удаления.
- `docs/06-maintenance.md`: «Полный сброс» требует ввода точной фразы подтверждения + обязательный бэкап; fail2ban/systemd вынесены как отдельное действие с sudo, не часть стандартной настройки.
- `core/05-protocol.md`: перед push — показать remote/ветку/список файлов + грепнуть на секреты; force push — только с явным ОК.
- `install.sh`: поддержка `DIRECTOR_REPO_REF` (пин на коммит/тег) и `DIRECTOR_EXPECTED_SHA256` (проверка целостности архива), печать SHA-256 скачанного архива.
