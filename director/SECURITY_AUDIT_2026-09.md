# Security-аудит Director — разбор и фиксы, 2026-09-05

Источник: `_inbox/feedback-director-oleg-lavrentev.md` — независимый обзор от пользователя (установка на Hermes, коммит `a04bab90bdd086c0f5955ec5af5091067436bbfe`, SHA-256 install.sh и архива приложены). Все 12 пунктов сверены с кодом лично — подтвердились все 12, плюс найден дополнительный баг (дефолтный пароль Postgres).

Формат по каждому пункту: **было → стало → почему**.

---

## 1. MCP подключается с автосогласием на все инструменты

**Было:** `adapters/hermes.md` — `printf 'y\n' | hermes mcp add ...`, `npx -y` без версии, пользователь не видит какие инструменты дал.
**Стало:** показываем список серверов и инструментов до подключения, PostgreSQL по умолчанию read-only (write — отдельный явный вопрос), `hermes mcp list` в конце показывается пользователю as-is.
**Почему это было плохо:** пользователь разрешал доступ, не понимая, что именно разрешает — включая запись в БД. «Enable all tools?» отвечать `y` за него = решение вместо него о его же данных.

## 2. Внешняя память может получать личные данные без согласия

**Было:** `AGENTS.md`/`CLAUDE.md` (LightRAG) — «сохраняй немедленно, не спрашивай», авто-запись каждого сообщения по команде «сохраняй всё» без предупреждения что это значит.
**Стало:** явное согласие пользователя перед подключением удалённой памяти (где физически стоит, что будет сохраняться), категории «можно / нельзя без отдельного разрешения» (мед. данные, клиентские тайны, документы, пароли — в чёрный список по умолчанию), команды на просмотр/экспорт/удаление описаны, файловая память — равноправный вариант, не «урезанный».
**Почему это было плохо:** для человека, работающего с чужими чувствительными данными (в фидбеке — арт-терапевт с данными пациентов), «сохраняй молча» = утечка третьим лицам без их ведома.

## 3. `eval` на пользовательском вводе

**Было:** `install.sh` (lightrag) — `eval "${varname}='${val}'"` в 3 местах. Спецсимволы во вводе (`'; rm -rf ~; echo '`) выполняются как команда.
**Стало:** `printf -v "$varname" '%s' "$val"` + валидация имени переменной regex'ом. Проверено локально инъекцией — не сработала.
**Почему это было плохо:** реальная RCE через ответ на обычный вопрос мастера («Домен?», «API endpoint?»).

## 4. Ключи и пароли сохраняются и печатаются небезопасно

**Было:** `.env` без `chmod`, пароль/API-ключ/JWT печатались в терминал полностью, `POSTGRES_PASSWORD=rag` захардкожен (найдено дополнительно, не было в фидбеке).
**Стало:** `umask 077` + `chmod 600` на `.env` и `docker-compose.yml`; в терминал — только последние 4 символа + путь к `credentials.txt` (chmod 600, полные значения только там); `POSTGRES_PASSWORD` генерируется (`openssl rand -hex 20`) + рантайм-проверка после старта контейнера (образ `gzdaniel/postgres-for-rag` иногда игнорирует переменную — теперь скрипт это обнаруживает и предупреждает, а не молчит).
**Почему это было плохо:** терминал попадает в scrollback/логи/скриншоты; дефолтный пароль БД = защиты по сути нет.

## 5. Docker ставится удалённым скриптом с sudo

**Было:** установщик сам делал `curl -fsSL https://get.docker.com | sh` + `usermod -aG docker`.
**Стало:** установщик останавливается, показывает команды и объясняет, что группа `docker` ≈ root, просит поставить руками и перезапустить установщик.
**Почему это было плохо:** непрошенный удалённый код + повышение прав без ведома пользователя — именно то, от чего людей предупреждают не делать вслепую.

## 6. Непинованные версии

**Было:** `ghcr.io/hkuds/lightrag:latest`.
**Стало:** закреплено на `1.4.9` во всех местах (`install.sh`, `docker-compose.yml`, доки), с комментарием проверять changelog перед обновлением.
**Не полностью:** `npx -y <pkg>` без версии остаётся в паре мест (MCP-сервера) — зафиксировать версию сложнее без своего npm-lock-файла; отмечено как задача на следующий релиз.

## 7. Разрушительные команды в документации

**Было:** `docs/02-server-setup.md` — `rm -f ~/lightrag/.env` без вопросов; `docs/06-maintenance.md` — снос Docker-volume и правка `fail2ban`/systemd без явного шага подтверждения.
**Стало:** удаление `.env` заменено на бэкап-копию + требование явного согласия; полный сброс требует ввода точной фразы подтверждения и обязательного бэкапа; fail2ban/systemd явно помечены как отдельное действие с sudo, не часть обычной установки.
**Почему это было плохо:** прямое противоречие с `core/03-rules.md» («не затирать существующее без согласия») — агент мог выбрать более разрушительную из двух инструкций.

## 8. Git push без подтверждения перед самим push

**Было:** протокол финала коммитил и пушил как рутинный шаг без показа, что именно уходит.
**Стало:** добавлен обязательный шаг — показать remote, ветку и список файлов, прогнать грепом на секреты (`.env`, `API_KEY`, `PASSWORD`, `TOKEN`) перед commit; force push — только с явным ОК.
**Почему это было плохо:** для нетехнического пользователя push — необратимая публикация; без показа списка файлов легко отправить не то.

## 9. Мастер меняет глобальные файлы агента без diff

**Статус: не исправлено в этом релизе.** Требует отдельного шага «сгенерировать проект изменений → показать diff по каждому классу (SOUL.md/профиль/MCP/память) → подтвердить» — это архитектурная доработка мастера, не точечный фикс. Зафиксировано в CHANGELOG как следующий шаг.

## 10. Установщик Claude-центричен даже под Hermes

**Статус: не исправлено в этом релизе.** Нужно сначала определять активную среду и спрашивать куда ставить (`--target hermes`), а не копировать во все каталоги агентов по умолчанию. Следующий шаг.

## 11. Архив скачивается без проверки хеша

**Было:** всегда `main.tar.gz`, никакой проверки.
**Стало:** поддержка `DIRECTOR_REPO_REF` (пин на конкретный коммит/тег) и `DIRECTOR_EXPECTED_SHA256` (остановка при несовпадении), печать SHA-256 скачанного архива при каждой установке.
**Не полностью:** это не versioned-релиз с официально опубликованным хешем — полноценная инфраструктура GitHub Releases с подписью впереди.

## 12. Правила хорошие, но другие файлы им противоречат

Это не отдельный баг, а диагноз, и он подтвердился: `core/03-rules.md` требовал «не печатать секреты», «не затирать без согласия» — а `install.sh` и доки делали ровно это. Фиксы п.1–8 устраняют сами противоречия, а не только симптомы.
