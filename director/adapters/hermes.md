# Адаптер: Hermes

Hermes — постоянный агент (Telegram-гейтвей + Kanban + cron), не сессии. Факты — из локальной установки (`/usr/local/lib/hermes-agent`, `~/.hermes/`) и `_inbox/natalia_hermes_install.md`.

## Память — `native`

У Hermes **уже есть** штатная постоянная память (`~/.hermes/memories/MEMORY.md` + `USER.md` + история сессий). Директор пишет решения/факты/предпочтения в `~/.hermes/memories/MEMORY.md`, профиль — в `USER.md`, стартовый recall — штатным механизмом Hermes. Ничего ставить не нужно: **`MEMORY_BACKEND` для Hermes всегда `native`.**

Граф-память (LightRAG) в пакет не входит (с 1.3.0). Нужна — ставится отдельным проектом, потом `MEMORY_BACKEND` вручную меняется на `lightrag*` и MCP добавляется рядом. См. [../memory-setup/README.md](../memory-setup/README.md).

🔴 Данные пациентов/клиентов, секреты, чужая переписка (принцип 7) — не пишутся в штатную память без явного разрешения на конкретную запись.

## Механика

| Аспект | Как |
|--------|-----|
| Инструкции | блок между маркерами **в конец** `~/.hermes/SOUL.md`; существующий текст персоны не трогать |
| Профиль | `~/.hermes/memories/USER.md` (формат `key §` через `§`), **дополнить** |
| Доктрина | `~/.hermes/skills/director-doctrine/` = копии `core/00–04` + `models.md` + `skills.md`. **Если там уже есть персональная версия — не перезаписывать: показать diff, спросить, дописать между стабильными маркерами** |
| Оркестратор | `hermes config get model.default` |
| Протокол сессии (core/05) | **не применяется** — вместо него протокол задачи (в блоке ниже) |

## MCP

Директор на `native` памяти MCP-серверов **не требует** — визард ничего не подключает.

Если {{USER_NAME}} отдельно поднял граф-память и хочет её подключить: команды `hermes mcp add` сверять с **фактическим** `hermes mcp add --help` установленной версии (флаги и порядок опций между версиями менялись), пакеты — с закреплённой версией (`@g99/lightrag-mcp-server@…`, `@modelcontextprotocol/server-postgres@…`), «Enable all tools?» — **не отвечать `y` вслепую**, выбрать `select`. Это вне сборки директора.

### Протокол задачи (на каждое обращение / карточку Kanban)
1. Прочитать карточку/сообщение целиком
2. Поднять контекст по теме — штатная память Hermes (`~/.hermes/memories/`). «🔍 Смотрю…» если >3 сек
3. Трогает реальных людей / прод ({{PROD_DEFINITION}})? → ОК {{USER_NAME}}, не раньше
4. Затратная задача (много ходов) → «⚠️ лучше с компьютера», ждать
5. Делать, делегируя: {{CHEAP_STACK}}
6. Проверить лично — curl/логи, не «✅»
7. Записать выводы (решения / паттерны / уроки, не пересказ) в `~/.hermes/memories/MEMORY.md`. **Принцип 7:** чувствительное — не писать
8. **Git — не обязательно.** Только если задача в репозитории И {{USER_NAME}} просил зафиксировать: `git add` конкретных файлов → показать remote/ветку/файлы + прогон на секреты → **спросить «запушить? [да/нет]»** → только после «да» commit + push
9. Отчёт в карточку: записал в память / сделано / проверено / (запушено или коммит локальный) / осталось. Не завершается → сказать {{USER_NAME}}, не зависать
