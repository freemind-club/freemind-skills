# Шаг 1: Обязательные вопросы

⛔ **НЕ НАЧИНАЙ УСТАНОВКУ**, пока не получишь ответы на ВСЕ обязательные вопросы ниже.

⛔ **ЕСЛИ НА СЕРВЕРЕ УЖЕ ЕСТЬ `~/lightrag/.env` ОТ ПРОШЛОЙ УСТАНОВКИ — ИГНОРИРУЙ ЕГО.** Не читай старый `.env` как источник значений. Всегда создавай `.env` заново из `.env.example`, спрашивай ВСЕ значения у пользователя и генерируй новые секреты.

---

## Принцип: спрашивай только то, что не можешь узнать сам

Если у тебя есть SSH-доступ к серверу — **проверяй сам**, не спрашивай пользователя:
- Установлен ли Docker → `docker --version`
- Какой reverse proxy стоит → `systemctl`, `docker ps`
- Есть ли существующие конфиги → `ls`, `cat`

**Спрашивай пользователя ТОЛЬКО то, что невозможно определить автоматически.**

---

## Вопросы, которые НУЖНО задать:

### 1. Куда ставим LightRAG?

Если пользователь дал IP-адрес и SSH-кредсы — это сервер, не спрашивай.

- **На удалённый сервер (VPS/dedicated)?**
  - → Переходи к вопросу 2 (домен)
- **Локально (Mac/Linux)?**
  - Домен не нужен, будет `localhost:9621`
  - → Пропусти вопрос 2, переходи к вопросу 3

### 2. Домен (ТОЛЬКО для серверной установки)

⛔ **ЭТО КРИТИЧЕСКИ ВАЖНЫЙ ВОПРОС. НЕ ПРОПУСКАЙ.**

- Нужен ли доступ к LightRAG с других машин (Mac, ноутбук, другой сервер)?
  - **Да** → НУЖЕН домен. Спроси какой.
  - **Нет, все агенты на этом же сервере** → Домен не нужен, `localhost:9621`.

- Если нужен домен:
  - Какой домен/субдомен? (например `lrag.example.com`)
  - DNS A-запись уже создана? (`домен → IP сервера`)
  - Если нет — пользователь должен создать её ПЕРЕД установкой.

**Почему это важно:**
- Без домена на сервере: LightRAG доступен ТОЛЬКО по `127.0.0.1:9621`. Агенты с других машин подключиться НЕ смогут.
- С доменом: доступен по `https://lrag.example.com` через HTTPS с API-ключом.
- Домен влияет на: `CORS_ORIGINS`, проброс портов в docker-compose, нужность reverse proxy.

### 3. LLM-провайдер

Предлагай значения по умолчанию. Пользователь подтвердит или изменит.

- **API endpoint** — по умолчанию `https://polza.ai/api/v1`
- **API-ключ** — спроси (обязательно, кроме Ollama)
- **LLM модель** — по умолчанию `google/gemini-2.5-flash-lite` (дёшево и быстро, хватает для извлечения сущностей)
- **Embedding модель** — по умолчанию `openai/text-embedding-3-small`

Соответствие провайдер → URL:
| Провайдер | URL |
|---|---|
| Polza.ai | `https://polza.ai/api/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| OpenAI | `https://api.openai.com/v1` |
| Ollama | `http://host.docker.internal:11434` (для Docker) |

### 4. Reverse proxy (ТОЛЬКО для серверной установки с доменом)

⛔ **НЕ СПРАШИВАЙ пользователя про reverse proxy — ПРОВЕРЬ САМ через SSH.**

Если есть доступ к серверу (SSH), выполни:
```bash
systemctl is-active caddy 2>/dev/null       # → active = Caddy (systemd)
docker ps | grep -iE 'nginx|proxy|npm'      # → есть = Nginx Proxy Manager
docker ps | grep caddy                       # → есть = Caddy (Docker)
docker ps | grep traefik                     # → есть = Traefik
```

На основе результата:
- **Caddy (systemd)** → добавь блок в существующий Caddyfile
- **Caddy (Docker)** → подключи к docker-сети LightRAG
- **Nginx Proxy Manager** → выдай инструкцию пользователю (добавить Proxy Host в UI)
- **Traefik** → выдай инструкцию пользователю (добавить labels или file provider)
- **Ничего нет** → установи Caddy через Docker в docker-compose
