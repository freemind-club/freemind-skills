# LightRAG — Единая база знаний для AI-агентов

Автоматическая память для Claude Code, OpenClaw и Paperclip.
Агенты сами ищут контекст и сохраняют важное — без ручных команд.

## Как это работает

```
Ты пишешь сообщение агенту
         │
         ▼
   Агент читает инструкции (CLAUDE.md / AGENTS.md)
         │
         ├──→ MCP: search("тема запроса") → LightRAG → релевантные факты
         │
         ├──→ Работает над задачей (с учётом найденного контекста)
         │
         ├──→ Появилось важное? → MCP: insert("факт") → LightRAG → граф знаний
         │
         └──→ Отвечает тебе
```

**Ключевое:**
- Поиск — при **каждом** твоём сообщении (фоново, ты не видишь)
- Сохранение — **сразу** когда появляется важное (не в конце сессии)
- Закрыл терминал — всё уже сохранено

## Что сохраняется, а что нет

| Сохраняется | Не сохраняется |
|---|---|
| Архитектурные решения | Опечатки, мелкие правки |
| Выбор технологий и причины | Промежуточная отладка |
| Найденные баги и решения | Тривиальные запросы |
| Предпочтения и требования | Временные значения |
| Информация о проектах | Дубликаты |

## Граф знаний

LightRAG не просто хранит факты — он строит **граф связей** между ними.

Факты из разных сессий:
1. "Проект Alpha на Next.js"
2. "В Alpha используем Supabase"
3. "Supabase Auth с JWT"

Граф: `Alpha → Next.js`, `Alpha → Supabase → Auth → JWT`

Вопрос "Как авторизация в Alpha?" → находит всю цепочку.

## Стек

| Компонент | Назначение |
|---|---|
| **LightRAG** | Граф знаний + RAG (извлечение сущностей, гибридный поиск) |
| **PostgreSQL** | pgvector (векторы) + Apache AGE (граф), image: `gzdaniel/postgres-for-rag:16.6` |
| **LLM провайдер** | Polza.ai / OpenRouter / OpenAI — извлечение сущностей + эмбеддинги |
| **Reverse proxy** | Nginx Proxy Manager или Caddy — SSL + проксирование |
| **MCP** | `@g99/lightrag-mcp-server` — протокол связи агентов с LightRAG |
