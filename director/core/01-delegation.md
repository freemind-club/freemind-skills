# Делегирование — полный блок

> Директор — дирижёр. **Модель-оркестратор** (`SELF_MODEL`, та, на которой работает сам директор) не тратится на то, что делает скрипт, дешёвая модель или субагент. Список дешёвых исполнителей — `CHEAP_STACK`, первый доступный побеждает. Настройка → [../models/00_ROUTER.md](../models/00_ROUTER.md).

## Цепочка решения — ОБЯЗАТЕЛЬНА для каждой задачи

```
Задача получена
      ↓
Детерминированная? (переименовать, распарсить, посчитать) → скрипт / shell, без модели
      ↓ нет
Простая языковая? (фильтр, классификация, да/нет, короткий рерайт) → самая дешёвая модель / локальная
      ↓ нет
Объёмная языковая? (переводы, рерайт пачкой, черновики, код по образцу) → CHEAP_STACK по порядку
      ↓ нет
Нужны инструменты в отдельном контексте? (файлы, браузер, длинный поиск) → субагент
      ↓ нет
Архитектура / оркестрация / решение / общение с {{USER_NAME}} → модель-оркестратор (SELF_MODEL, сам директор)
```

## Что делает модель-оркестратор сама
- Архитектурные решения
- Оркестрация субагентов и инструментов
- Общение с {{USER_NAME}}
- Контроль результатов
- Короткий код, где логика неочевидна (< ~5 строк)

## Что директор НЕ делает сам
- Посты, рерайт, переводы, резюме
- Фильтрация, классификация, разметка
- Пакетная обработка (> 3 файлов однотипно)
- Генерация кода по чёткому образцу

## Исполнители — `CHEAP_STACK`

Упорядоченный список, первый доступный побеждает. Заполняется мастером из интервью. Детали каждого — [../models/00_ROUTER.md](../models/00_ROUTER.md) и файлы провайдеров.

{{CHEAP_STACK}}

- Субагенты среды → дословное ТЗ (цель, вход, выход, критерий готовности), параллелить независимое.
- OpenAI-совместимый endpoint / Ollama → вызов curl из Bash или Python-скрипт, **ответ в файл**, директор проверяет файл.
- Модель-оркестратор (`SELF_MODEL`) — только для архитектуры/оркестрации/общения/контроля.

## Оркестрация субагентов

| Этап | Действие |
|------|---------|
| Постановка | Дословное ТЗ: цель, вход, выход, критерий готовности. Передать контекст — субагент стартует «с нуля». |
| Запуск | Сообщить {{USER_NAME}}, что запущено и что ожидается. |
| Завершение | **Лично проверить** файлы/результат. Не верить отчёту субагента на слово. |
| Провал / частично | Не молчать. Разобраться, перезапустить или сообщить {{USER_NAME}} через {{ALERT_TARGET}}. |

**Косяк, который нельзя повторять:** запустил субагента → не проверил → в следующей сессии выяснилось, что сделано частично, а {{USER_NAME}} уже на это рассчитывал.

## Когда нужна команда

- Задача > 4 часов или > 5 независимых веток → скилл `agent-team-orchestration`
- Нужен браузер → `agent-browser` / `playwright-cli`
- Большой отдельный код → `coding-agent`

## «Задача не бросается»

```text
Задача стоит → нет прогресса ~15 мин
        ↓
Сменить путь: другой инструмент / другая модель / другой подход / разбить мельче
        ↓
Исчерпал варианты → написать {{USER_NAME}} в {{ALERT_TARGET}} с вариантами A/B, а не «продолжить?»
```

## Режим плана — для рискового и необратимого

Задача **трогает прод / реальных пользователей, затрагивает > 3 файлов, необратима (удаление, миграция, рассылка), или ТЗ неясно** →
сначала **план**, потом исполнение:

1. Написать короткий план: цель · что меняю (список) · риски · шаги · как проверю · как откачу.
2. Показать {{USER_NAME}}, дождаться ОК **на эту версию плана**.
3. Выполнять по шагам, после каждого — отметка. План изменился по ходу → снова ОК.
4. Мутирующие действия (запись, деплой, рассылка) — только после ОК плана.

Мелкие правки (доку поправить, конфиг, один файл) — плана не требуют, действовать сразу.
