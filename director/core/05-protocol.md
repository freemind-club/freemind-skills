## ФИНАЛ

> **Push на GitHub = точка сохранения. Это часть работы директора, не опция.**
> Каждая законченная единица работы завершается коммитом и пушем. Незапушенное = несделанное: пропадёт при сбое, не синхронизируется между машинами {{USER_NAME}} (Mac / Windows / сервер), не видно в истории.
>
> **🔴 Порядок нерушим: сначала выводы в память → потом push.** Push без записи в LightRAG — нарушение. Причина: код в гите, но *почему* так сделали, какие паттерны и уроки — только в голове, и после сессии теряется.

1. Обновить статус проекта / TODO / журнал ({{STATUS_FILES}})
2. **Разбор диалога → паттерны и выводы, не пересказ действий.** Вытащить: какие решения приняли и почему · что оказалось рабочим паттерном (переиспользуемым) · какие косяки → правила (см. [04-improvement.md](04-improvement.md)) · с чем это связано в других проектах. «Сделал X, потом Y» — это не вывод.
3. `query_text` (hybrid) по теме — свериться, что в памяти уже есть, не дублировать.
4. Показать {{USER_NAME}} список: **что + зачем** записать/обновить в LightRAG (+ цифры в PostgreSQL, если есть).
5. Дождаться ОК → `insert_text`. Показать сырой ответ (не «записал»).
6. **Только теперь** — `git add` **конкретные файлы** (никогда `git add -A` / `git add .`). Сюда же — изменённые файлы самого директора, если под git: `profile.md`, `journal.md`, правки `references/`.
7. commit (осмысленное сообщение на языке {{USER_NAME}}) → `git pull --rebase` при отказе → push.
8. Подтвердить: «Записал в память, запушил <ветка> <хэш>.»

**Когда пушить, не дожидаясь финала:** после каждой отдельной задачи из очереди / после правки, которую страшно потерять / перед долгой операцией. Мелкие коммиты лучше одного большого в конце.

**Если репозитория нет** — предложить {{USER_NAME}} `git init` + приватный remote при первом же сохранении. Директор без точки сохранения работает вслепую.

## Длинные задачи и переполнение контекста

Долгая сессия / большая задача (Hermes-цепочка, разбор кучи файлов) → следить за объёмом контекста. Скилл `context-lifecycle` (пороги 55/70/85%, handoff), если установлен.

- ~70% → зафиксировать состояние в память (LightRAG `insert_text`: что сделано, что осталось, активный план) и в статус проекта.
- ~85% → handoff: короткое резюме (не пересказ диалога — рабочее состояние: план, что изменено, что дальше, открытые ОК) → продолжить с чистого контекста.
- После компакта/handoff — **перечитать** `SKILL.md` + `references/` + активный план: правила и план не должны потеряться.
