# Стандарт скиллов FreeMind — версии, история, документация

> Для всех авторских скиллов Олега. Цель: любой скилл можно спокойно обновлять, зная что менялось и как откатиться.

## 1. Версия — у каждого скилла

В `SKILL.md` frontmatter:

```yaml
---
name: skill-name
description: ...
metadata:
  version: "1.0.0"
---
```

**Semver `X.Y.Z`:**
- `X` — ломающее изменение (сменился формат вызова, убрали раздел, поменяли поведение)
- `Y` — новая возможность, обратно совместимо
- `Z` — фикс, уточнение формулировки, опечатка

Первая фиксация существующего скилла → `1.0.0`.

## 2. История изменений

> **Где живёт `CHANGELOG.md`:** в исходнике/репо скилла (для GitHub — студенты видят историю). **Не** копируется в рантайм-установку `~/.claude/skills/` и **не** ссылается из `SKILL.md` — значит не грузится в контекст. `skill-conductor` пометит его как «лишний файл» при проверке исходника — это единственное принятое исключение (проверяй рантайм-копию: `~/.claude/skills/<name>` → должно быть 10/10).

**Крупные скиллы** (`director`, `oleg-core`, `oleg-post-writer`, `n8n-agent`) — отдельный `CHANGELOG.md` в корне:

```markdown
# CHANGELOG — skill-name

## [1.1.0] — 2026-09-10
### Добавлено
- ...
### Изменено
- ...
### Исправлено
- ...

## [1.0.0] — 2026-09-02
- Первая версия.
```

**Маленькие скиллы** (1 файл, `tg-notify`, `tg-audit`, `mom-test-questions`, `claude-to-im`, `freemind-platforms`, `claude-director`) — секция в конце `SKILL.md`:

```markdown
## История

- **1.0.1** (2026-09-10) — уточнил формат X
- **1.0.0** (2026-09-02) — первая версия
```

## 3. Документация

- **Локально:** в папке скилла. `SKILL.md` + `CHANGELOG.md`/История + (для крупных) `OVERVIEW.md` (что, зачем, архитектура, что осталось).
- **GitHub:** `freemind-club/freemind-skills` (канон) — папка на скилл, README-таблица репо: `скилл | версия | назначение | обновлён`.

## 4. Процесс обновления скилла

1. Правка в источнике (папка скилла в репо `freemind-skills`, либо `04_projects/*` для локальных)
2. **Bump версии** в frontmatter
3. Запись в `CHANGELOG.md` / «История»
4. `skill-conductor` (Mode 4 REVIEW / Mode 3 VALIDATE) — структура + триггеринг ок
5. commit (сообщение: `skill-name: v1.1.0 — краткая суть`) → push
6. Скиллы, у которых есть механизм проверки обновлений (как `director` с `VERSION`) — пользователь увидит «доступно обновление»

## 5. Правило коммита

Скилл изменён, а версия не поднята → это ошибка. Проверять глазами при ревью push (позже — hook).

## 6. Как раздаётся

- **Основное:** `install.sh` в корне репо (curl | bash), + свой `install.sh` у скилла с гейтом (director).
- **Обновление:** повторный запуск установщика ставит свежие версии поверх.
- **`.skill`-файлы** (опц., для «скачать один скилл»): собираются `skill-conductor/scripts/package_skill.py <skill>` и кладутся в GitHub Releases.

## 7. Синхронизация версий

`SKILL.md` → `metadata.version` = **единственный источник правды**. Таблица в `README.md` и вывод `install.sh --list` берутся из него. При bump — обновить и таблицу в README.
