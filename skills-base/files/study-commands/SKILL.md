Пользователь даёт документ (файл, вставленный текст, ссылку) и одну или несколько команд из списка в `references/komandy.md`. Твоя задача — найти команду в списке и применить ровно её формат к ровно этому документу.

## Когда срабатывает

- Пользователь прислал документ/текст и попросил конспект, разбор, визуализацию, карточки, план действий или похожее.
- В сообщении есть слово из списка команд — со слэшем (`/mindmap`) или без (просто «сделай майндмап»).
- Явный вызов: `/study-commands <команда> <документ или ссылка на него>`.

## Инструкции

### Шаг 1. Определи документ

Если документ не приложен и не вставлен текстом — спроси, что разбирать. Не выдумывай содержание документа, которого не видел.

### Шаг 2. Определи команду

1. Найди слово команды (из `references/komandy.md`) в сообщении пользователя — со слэшем или без, регистр не важен.
2. Нашёл одну — применяй её формат (раздел «Как оформить» у этой команды в `references/komandy.md`).
3. Пользователь попросил своими словами, без точного слова команды («сделай попроще», «покажи схемой») — подбери ближайшую по смыслу команду сам, скажи какую выбрал.
4. Команда не названа вообще, просто «разбери документ» — предложи `/fullstudy` как сборный формат и спроси, подходит ли, или пусть выберет конкретную из списка (покажи 5-7 самых популярных по категориям).
5. Попросили несколько команд сразу («конспект и майндмап») — сделай обе по очереди, разделы отдельными заголовками.

### Шаг 3. Примени команду

Открой `references/komandy.md`, найди точное описание нужной команды и строго следуй её формату «Как оформить». Используй только то, что есть в документе — ничего не добавляй от себя, кроме явно обозначенных выводов/мнений, где это часть формата команды (`/critique`, `/counterpoints` и т.п. — там обозначай это как анализ, не как факт из документа).

### Шаг 4. Проверь перед выдачей

- Все факты и цитаты — из документа, не из общих знаний о теме.
- Формат соответствует именно той команде, которую просили (не перепутать `/executivesummary` с `/fullsummary`).
- Если документ слишком короткий/не подходит под формат команды (например, просят `/timeline` у текста без единой даты) — скажи об этом прямо, не натягивай.

## Правила

- Никогда не выдумывай содержание документа, которого не получил.
- Факты и цитаты — только из документа. Общие знания по теме — только если формат команды явно это предполагает (например, `/businessapplication` может предлагать своё применение).
- Если команда не найдена в списке и не удалось подобрать ближайшую — так и скажи, не изобретай формат на ходу.
- Не путай это со встроенными командами ChatGPT/Гермеса — это просто словарь форматов, который понимаешь ты сам по этой инструкции.

## Examples

### Типичный запрос
Пользователь: «Вот статья [текст]. /mindmap»
Результат: открываешь `komandy.md` → `/mindmap` → строишь майндмап от центральной идеи статьи, ветки — по разделам из `references/komandy.md`.

### Граничный случай
Пользователь: «/timeline» + документ без единой даты/хронологии.
Результат: «В этом документе нет дат и последовательности событий — `/timeline` не подойдёт. Хочешь `/flowchart` (процесс) или `/mindmap` (темы без хронологии) вместо этого?»
