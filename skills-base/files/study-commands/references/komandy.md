# Словарь команд — 50 форматов изучения документа

Источник идеи: подборка «Топ 50 команд ChatGPT для изучения любой темы» (дамп Мимира 05.10.2026, оригинальный источник — внешний Telegram-канал, список переформулирован и дополнен конкретикой для надёжного исполнения).

Каждая команда — **что это** (коротко) + **как оформить** (конкретный формат вывода, чтобы не плыло от раза к разу).

---

## Конспекты и объяснения без лишней воды

### /executivesummary
Главная мысль и выводы автора.
**Как оформить:** 3-5 предложений. Сначала главный тезис документа одной фразой, потом 2-4 ключевых вывода списком.

### /fullsummary
Саммари с разделами и подразделами.
**Как оформить:** структура документа сохраняется — заголовок раздела оригинала → 2-4 предложения сути. Не короче четверти документа по охвату тем, но компактно по словам.

### /quicksummary
Суть за пару пунктов.
**Как оформить:** максимум 3 пункта, каждый — одно предложение. Для человека, у которого 20 секунд.

### /chapterbychapter
Пересказ каждой главы.
**Как оформить:** если в документе есть главы/разделы — один абзац (3-5 предложений) на каждую, с названием главы как подзаголовком. Нет явных глав — раздели по смысловым блокам сам, скажи что деление твоё.

### /coreideas
Ключевые идеи.
**Как оформить:** список 5-8 идей, каждая — заголовок жирным + одно предложение пояснения.

### /studynotes
Готовый конспект: источник, тезис, понятия, выводы.
**Как оформить:** четыре раздела ровно в этом порядке — «Источник» (что за документ), «Главный тезис» (1 фраза), «Ключевые понятия» (список термин → определение), «Выводы» (список).

### /explainsimply
Простыми словами, без сложных терминов.
**Как оформить:** перескажи суть так, как объяснил бы умному подростку. Специальный термин — сразу расшифровка в скобках. Короткие предложения.

### /explainwithexamples
Пример из жизни к каждому понятию.
**Как оформить:** для каждого ключевого понятия документа — определение + один бытовой пример, не из документа, а придуманный по аналогии (явно пометь «пример для наглядности»).

### /glossary
Словарь терминов.
**Как оформить:** алфавитный или по порядку появления список «термин — определение простыми словами», только термины реально встреченные в документе.

### /questionsanswered
Главные вопросы по теме с готовыми ответами.
**Как оформить:** 5-7 пар «Вопрос? → Ответ из документа» — вопросы такие, какие реально задал бы любопытный читатель.

## Визуализация темы

Для всех визуализаций: если доступен инструмент отрисовки (диаграммы/изображения) — используй его. Нет — опиши структуру текстом в виде вложенного списка или ASCII-схемы, явно скажи «текстовое представление, не картинка».

### /visuallearning
Подбор наглядного формата под материал.
**Как оформить:** посмотри на содержание документа и сам выбери 1-2 подходящих формата из списка ниже (mindmap/timeline/flowchart и т.д.), сделай их, объясни почему выбрал именно эти.

### /visualsummary
Краткое содержание схемой/картинкой.
**Как оформить:** одна схема — центр (главная тема) + 3-5 веток (ключевые блоки), без глубокой вложенности.

### /mindmap
Тема расходится ветками от центра.
**Как оформить:** центральный узел — тема документа, ветки первого уровня — главные разделы, ветки второго уровня — подпункты. Минимум 2 уровня, максимум 3.

### /conceptmap
Связи между понятиями.
**Как оформить:** список понятий + стрелки с подписью связи («А влияет на Б», «В — часть Г»), не просто иерархия как в mindmap, а именно связи между разными узлами.

### /infographic
Собрать инфографику.
**Как оформить:** 3-6 блоков с цифрой/фактом + короткой подписью к каждому, в порядке важности. Если есть инструмент генерации изображений — создай картинку; нет — текстовый макет блоков.

### /sketchnote
Нарисованный конспект на одну страницу.
**Как оформить:** одна страница: заголовок, 3-5 ключевых блоков с короткими подписями и предложенными мини-иконками/символами рядом (текстом, если рисовать нечем).

### /timeline
События на временной шкале.
**Как оформить:** список «дата/момент → событие», строго в хронологическом порядке. Если в документе нет дат/последовательности — скажи прямо, не натягивай, предложи `/flowchart` или `/mindmap` вместо.

### /flowchart
Схема процесса: шаги, решения, причины-следствия.
**Как оформить:** пронумерованные шаги, точки ветвления — явно «если… → иначе…». Нет процесса в документе — скажи и предложи другой формат.

### /comicstrip
Ключевые мысли в формате комикса.
**Как оформить:** 4-6 «кадров», каждый — короткая сценка/реплика + подпись, передающая одну мысль документа. Текстовый сценарий кадров, если нет генерации изображений.

### /visualanalogies
Сложные понятия через наглядные сравнения.
**Как оформить:** для 3-5 сложных понятий документа — «это как [бытовая аналогия], потому что [в чём сходство]».

## Штудируем изученное и делаем шпаргалки

### /flashcards
Карточки вопрос-ответ.
**Как оформить:** 10-15 карточек, формат «Вопрос: … / Ответ: …», ответ короткий (1-2 предложения).

### /visualflashcards
Карточки с понятием, примером и образом.
**Как оформить:** та же структура, что `/flashcards`, плюс третья строка «Образ для запоминания: …» (яркая мысленная картинка-ассоциация).

### /quiz
Тест с вариантами и разбором.
**Как оформить:** 5-10 вопросов, 4 варианта ответа (A-D), один верный. После всех вопросов — отдельный блок с правильными ответами и однострочным объяснением к каждому.

### /reviewquestions
Прямые вопросы для повторения.
**Как оформить:** 8-12 открытых вопросов без вариантов ответа, без подсказок — проверка, помнит ли человек сам.

### /activerecall
Упражнения на запоминание.
**Как оформить:** 5 заданий вида «закрой документ и напиши по памяти: …» на разные части материала.

### /spacedrepetition
Интервальный график повторений.
**Как оформить:** таблица «что повторять | когда (день 1 / день 3 / день 7 / день 14 / день 30)» для 5-8 ключевых блоков материала.

### /fillintheblanks
Текст с пропусками.
**Как оформить:** 8-10 коротких предложений из сути документа с одним пропущенным ключевым словом каждое, плюс отдельно список ответов в конце.

### /trueorfalse
Верно/неверно.
**Как оформить:** 10 утверждений по материалу (часть верных, часть намеренно искажённых), ответы — отдельным блоком в конце с кратким объяснением неверных.

### /mockexam
Пробный тест.
**Как оформить:** смешанный формат — 5 вопросов с вариантами + 3 открытых вопроса + 1 практическое задание, как настоящий экзамен по материалу.

### /studysheet
Шпаргалка на одну страницу.
**Как оформить:** максимально плотно — заголовки-термины жирным, рядом однострочное определение/формула/факт, без пояснений и воды, только то что нужно вспомнить быстро.

## Анализируем и собираем своё мнение

### /argumentmap
Карта аргументов.
**Как оформить:** главный тезис автора вверху, под ним — аргументы в его поддержку (список), под каждым — на чём он основан (данные/примеры из документа).

### /bookthesis
Главная идея автора.
**Как оформить:** 1-2 предложения — что именно автор хочет доказать или донести, без пересказа содержания.

### /evidence
Чем автор подкрепляет доводы.
**Как оформить:** список «утверждение автора → какими данными/примерами/ссылками подкреплено (или не подкреплено — отметь явно)».

### /counterpoints
Возражения оппонента.
**Как оформить:** для 3-5 главных тезисов документа — по одному реалистичному возражению, которое мог бы привести думающий оппонент. Явно помечай «это контраргумент, не позиция документа».

### /critique
Слабые места в рассуждениях.
**Как оформить:** список конкретных слабых мест — нелогичный переход, недоказанное утверждение, однобокость — с указанием, где именно в документе это встречается.

### /biases
Предвзятость и отклонения.
**Как оформить:** список найденных признаков предвзятости (однобокий подбор примеров, эмоциональная лексика вместо аргументов, умолчание о противоположной точке зрения) с цитатой-иллюстрацией из документа к каждому.

### /mythsvsfacts
Факты vs небылицы.
**Как оформить:** таблица в две колонки — «Миф/непроверенное утверждение» | «Что говорят факты/данные», только по утверждениям из документа.

### /compareideas
Сравнение идей из разных источников.
**Как оформить:** нужен второй документ/источник от пользователя для сравнения — если его нет, спроси. Есть — таблица «аспект | источник 1 | источник 2» по 4-6 ключевым аспектам.

### /deepquestions
Вопросы для самостоятельного размышления.
**Как оформить:** 5-7 открытых вопросов без ответов, выходящих за рамки документа, провоцирующих подумать дальше темы.

### /conclusions
Итоговые выводы.
**Как оформить:** 3-5 выводов, которые следуют из материала, без добавления выводов, которых в документе не было.

## Превращаем изученное в конкретные действия

### /actionplan
Выводы → конкретный план.
**Как оформить:** нумерованный список шагов «что сделать», каждый шаг — конкретное действие с глаголом в начале, не абстракция.

### /fullstudy
Весь путь: резюме, карта, карточки, тест, критика, план.
**Как оформить:** последовательно разделами: `/quicksummary` → `/mindmap` → `/flashcards` (5-7 штук, не 15) → `/quiz` (3-5 вопросов) → `/critique` (кратко) → `/actionplan`. Сборный формат, каждый раздел короче, чем если бы делали его отдельно.

### /practicalinsights
Уроки, применимые прямо сейчас.
**Как оформить:** 3-5 пунктов «что можно применить уже сегодня», без теории, только практика.

### /checklist
Чек-лист для выполнения.
**Как оформить:** список `[ ] пункт` — конкретные проверяемые шаги/условия из материала, в порядке выполнения.

### /7daychallenge
Семидневный челлендж от простого к сложному.
**Как оформить:** 7 дней, каждый день — одна конкретная задача по нарастающей сложности, основанная на материале документа.

### /habits
Идеи → ежедневные задачи.
**Как оформить:** 3-5 привычек, каждая — формат «когда [триггер] → делаю [действие]», основано на материале.

### /casestudy
Разбор на реальных примерах.
**Как оформить:** если в документе есть кейсы/примеры — разбери 1-2 подробно (ситуация → что сделали → результат → чему учит). Нет готовых кейсов — построй гипотетический по логике документа, явно пометь «гипотетический пример».

### /businessapplication
Применение в работе и бизнесе.
**Как оформить:** 3-5 пунктов «как это использовать в бизнесе/на работе прямо сейчас», конкретно, не общими словами.

### /feynmanmethod
Проверка понимания — объяснить своими словами.
**Как оформить:** сначала ты объясняешь тему максимально просто (как будто пользователю 10 лет), потом даёшь пользователю вопрос «а теперь объясни мне своими словами» и ждёшь ответа — не отвечай за него.

### /lessonplan
План занятия, чтобы объяснить тему другому.
**Как оформить:** структура урока — цель, 3-5 этапов с таймингом (вступление/объяснение/практика/проверка/итог), материалы/примеры к каждому этапу.
