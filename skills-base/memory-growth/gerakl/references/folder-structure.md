# Эталон логической структуры папок (зона 8 Геракла)
> Предлагается пользователю ОДИН раз, на первом субботнике. Выбор за ним: «оставить как есть» или «разложить по разделам». Номера разделов закреплены, чтобы у любого клиента «04» было аналитикой.

## Клиент — `<папка клиентов>/<Имя Фамилия>/`
```
README.md                 карточка + навигация (без паролей)
СТАТУС.md                 что работает / что осталось — открывать первым
01_Договор_и_деньги/      КП, договор, счета, оплаты, акты
02_Встречи_и_переписка/   встречи, договорённости, вопросы и тексты к отправке
03_Техника/               сервер, установка, журнал отката, инфраструктура, скрипты
04_Аналитика_и_отчёты/    отчёты и их код, разборы, подготовка к встречам
05_Маркетинг_и_продажи/   маркетинг, ЦА, скрипты продаж, рейтинги, отзывы
06_Обучение_клиента/      инструкции, уроки, памятки клиенту
07_Документы_клиента/     что прислал клиент, база знаний, «мозг»
99_Архив/
<любой раздел>/ДАННЫЕ/    не в git: цифры, выгрузки, переписка, бэкапы
```
Секреты клиента — отдельной папкой вне git (например `<служебная папка>/clients/<slug>/ДОСТУПЫ.md`).

## Проект — `<папка проектов>/<Название>/`
```
README.md, СТАТУС.md, TODO.md
01_Управление/  02_Исследования/  03_Продукт/  04_Код/
05_Маркетинг/   06_Аналитика/     07_Материалы/  99_Архив/
<любой раздел>/ДАННЫЕ/   не в git
```
Код живых сервисов не переносить без проверки, что сервисы после этого работают.

## Как предлагать
1. Взять ОДНУ реальную папку пользователя и показать «как сейчас» → «как было бы» (деревом, 10–15 строк).
2. Плюсы: зашёл в клиента → раздел → всё по теме; данные клиентов не утекут в git.
3. Цена: перенос и правка ссылок, по одной папке.
4. Вопрос: «Оставить как есть или разложить? Можно начать с одной папки на пробу».
5. Записать ответ и больше не предлагать без запроса.

## Если «разложить»
- Журнал отката (что → куда) ДО первого переноса.
- Папка за папкой; после каждой: grep старых путей по проекту и памяти, `git status --ignored` (ДАННЫЕ/ игнорируются), README с навигацией.
- В `.gitignore`: `<папка клиентов>/**/ДАННЫЕ/`.

## Верхний уровень рабочей папки (предложить вместе с зоной 8)
Если корень разросся (десятки папок, дубли номеров, одно и то же в 2–3 местах) — предложить, не навязывать:
```
00_<система>/   память агента, статусы, шаблоны, секреты (если путь зашит в хуки — имя НЕ менять)
01_clients/     клиенты
02_projects/    проекты; код ботов/сервисов — внутри своего проекта (04_Код/)
03_<контент>/   клуб, канал, посты
04_<бренд>/     личный бренд / продукт (если есть)
05_workshop/    мастерская: скиллы, промпты, черновики, инструменты, инструкции — одна папка вместо трёх
inbox/       входящие: от человека + от других агентов
99_archive/     архив
```
- Наверху латиница без пробелов; внутри — язык пользователя.
- Перед переносом: инвентаризация ссылок вне репо (хуки, settings, cron, systemd, конфиги/SOUL других агентов, память), пауза синхронизаций (Syncthing/облако) на других устройствах, git tag точки возврата.
- После: `.gitignore` — проверить, что общие правила (`_inbox/`, `**/ДАННЫЕ/`) не потерялись при замене путей; `git status` — нет новых неотслеживаемых секретов; запрещающие правила (deny) — и на новый, и на старый путь.
- Старые имена — временные symlink на неделю, затем удалить.


## Системная папка (зона 9, 11.11.2026)

Эталон корня (у владельца — `<системная папка>/`, прецедент 11.11.2026: ~40 → 15 элементов):

| Что | Где |
|-----|-----|
| Статус, задачи, каталог инструментов, таблицы моделей, каталог скиллов, стандарт скиллов | корень (по файлу) |
| Секреты | корень, вне git (`CREDENTIALS.md`, `clients/<slug>/`) |
| Ошибки/паттерны/runbook-и по темам | `kb/errors/`, `kb/patterns/`, `kb/*_RUNBOOK.md` |
| Разовые отчёты, закрытые HANDOFF, журналы шагов | `logs/` |
| Журналы переезда серверов | `logs/migration/` (вне git — там IP) |
| Шаблоны и скрипты создания папок | `templates/` |
| Устаревшее | `archive/` |
| Бэкапы, выгрузки | архив верхнего уровня (`99_archive/…`), вне git |
| Уроки, материалы курсов | раздел клуба/курсов, не системная папка |

Порядок разбора: инвентарь (размер, дата последнего коммита, сколько файлов ссылается) → предложение
в 3 группах (оставить / в архив / перенести по смыслу) + список «решить пользователю» → ОК →
журнал шагов → `.gitignore` для приватного ДО переноса → перенос (`git mv` для отслеживаемого) →
переписать ссылки в живых файлах → проверка: в коммите нет ключей и приватных файлов.
