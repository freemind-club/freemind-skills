# Syncthing — технические нюансы (пригодится при переезде)

> Найдено эмпирически 16-18.09.2026 при первой настройке Syncthing на сервере.
> При переезде на новый сервер Syncthing нужно поднимать заново — эти грабли повторятся, если
> не знать про них заранее.

## Гейт 7 (добавление к risk-gates.md) — заново поднять Syncthing на новом сервере

При переезде нужно: установить Syncthing на новом сервере, получить новый Device ID, переподключить
клиентские устройства к НОВОМУ серверу (не автоматически — Syncthing привязан к конкретному Device ID, старый
сервер не подменяется новым сам по себе). Пока это не сделано — клиентские устройства остаются
синхронизированы со СТАРЫМ (выключенным) сервером, что незаметно на первый взгляд (клиент просто
перестаёт получать обновления, не выдаёт явную ошибку сразу).

**Не гейт из risk-gates.md** (не необратимо), но легко забыть — включить явным пунктом в
`checklist.md`.

## Известный баг: негация в .stignore ненадёжна

**Симптом:** паттерн вида «запретить всё, потом разрешить конкретное» —
```
01_bots/**
!01_bots
!01_bots/*/
!01_bots/*/*.md
```
— синтаксически принимается Syncthing без ошибок (видно в `/rest/db/ignores`), но на практике
файлы, которые должны были «разрешиться» через `!`, остаются с флагом `ignored: true` даже после:
- обычного `POST /rest/db/scan`
- полного `systemctl restart syncthing@root`

**Рабочее решение:** не использовать негацию вообще. Инвертировать логику — по умолчанию
разрешено всё, явно запрещать только конкретные подпапки/расширения:
```
99_archive/01_bots_archive/**
01_bots/freemind_bot/**
01_bots/*/.claude/**
01_bots/*/logs/**
01_bots/**/*.py
01_bots/**/.env*
```
Этот стиль паттернов (простой блэклист, без `!`) отработал корректно с первого раза.

**Если очень нужна негация** (блэклист неудобен, слишком много подпапок с кодом) — после смены
паттернов ОБЯЗАТЕЛЬНО пересоздать саму папку в конфиге Syncthing (DELETE + POST `/rest/config/folders`
с тем же ID/путём), а не полагаться на rescan/restart — похоже, per-file флаг `ignored` кэшируется
в индексе и не пересчитывается для уже известных файлов при простой смене паттернов. Пересоздание
папки не трогает файлы на диске, только заставляет Syncthing перестроить индекс с нуля.

**Как проверить границу синка после любых правок `.stignore`** (использовать при переезде для
проверки нового сервера так же, как проверяли старый):
```bash
API_KEY=$(command grep -oP '(?<=<apikey>)[^<]+' ~/.local/state/syncthing/config.xml)
curl -s "http://127.0.0.1:8384/rest/db/file?folder=claudecode&file=<путь%2Fк%2Fфайлу>" \
  -H "X-API-Key: $API_KEY"
# Пустой ответ (404-подобный, "Expecting value" при парсинге) = файл не в индексе = точно не синкается
# JSON с "ignored": false = синкается
# JSON с "ignored": true = формально исключён, но см. баг выше — перепроверять после пересоздания папки
```
